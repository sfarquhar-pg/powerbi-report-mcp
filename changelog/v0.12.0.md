# v0.12.0 — Component fit engine, wrap-aware text fit, typography roles

## Summary

Extends `pbir_audit_style_consistency` from card-only overflow detection to a full **component fit engine**: every component type now has a documented minimum-size formula, textbox fit is wrap-aware, and typography is audited per ROLE so heading/title/legend/value levels stay consistent report-wide.

## New checks

| Code | Rule |
|---|---|
| `COMPONENT_UNDERSIZED` | per-type minimum sizes via exported `estimateMinSize()`: dropdown slicer = titleBar + header(text×1.8) + 30 input + 14 (≈62px @10pt header — field-verified against a hand-corrected live report where 48px clipped the input); list slicer = 3 visible items; charts = titleBar + legend + 120px plot; tables = titleBar + header + 2 rows; pageNavigator = text×2.6. `exempt: [visualId]` opts out ("scrollable unless asked"). |
| `TEXT_OVERFLOW` | wrap-aware textbox/shape-text fit via `estimateTextBox()`: char-width (fontSize×0.58) wraps into available width, wrapped lines × fontSize×1.8 + 10 must fit the box height. Encodes the practice: **always size a text box for its font**; when text sits on a background band, match the band height and give the width the text estimate + tolerance. |
| `TYPO_INCONSISTENT` | typography role census (visualTitle, cardValue, dataLabels, legend, axis, slicerHeader, slicerItems, tableHeaders, tableValues) — any role rendered at more than one size is flagged with the majority size to align to. Full census returned as `typography`. |

## Also

- `estimateMinSize` / `estimateTextBox` exported for programmatic sizing at build time (compute the box from the content before placing it, instead of validating after).
- Fixed `textboxContent` font detection (default 12 no longer floors smaller detected sizes).
- `skills/wireframes.md`: component minimum-size formula table, typography roles, textbox sizing practice, chart defaults (data labels on; line tooltips on unless asked).
- Tests 9 → 13 assertions in `scripts/test-style-audit.js`.
