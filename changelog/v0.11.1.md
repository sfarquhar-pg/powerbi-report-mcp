# v0.11.1 — Theme-driven typography + audit refinements

## Root cause found by dogfooding v0.11.0

Running `pbir_audit_style_consistency` against a real report exposed why themed typography kept "not applying": `createVisual` unconditionally injects `fontSize: 8` + `'Segoe UI', wf_segoe-ui_normal, ...` into every visual's title, axes, labels, legend and slicer items/header — explicit visual-level properties that silently override any report theme (`textClasses` / `visualStyles`). 138 injected Segoe references were found in a 79-visual report themed entirely in DIN.

## Changes

1. **`MCP_FONT_DEFAULTS=off`** (env): skips ALL implicit font/size injection in `pbir_add_visual` so the report theme drives typography. Default remains `legacy` (inject) for backward compatibility.
2. **Audit fix**: `MEASURE_FILTER_MISMATCH` no longer flags bare auto-filter placeholders (filter entries without a `filter.Where` body) — these are valid PBIR auto-filters, not broken conditions. New regression assertion.
3. **Activation fix for v0.10.0–0.11.0 tools**: `pbir_fabric_mirror_style` and `pbir_audit_style_consistency` were registered but missing from the `ALL_TOOLS` activation list in `src/index.ts` — callers got "Tool not found". Both added; tool surface test now reflects 64 active tools. (The surface test compares registered-vs-source lists, so a tool missing from BOTH passes silently — worth a future guard that greps `server.tool(` calls.)
