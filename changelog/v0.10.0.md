# v0.10.0 — Style mirroring from a report link

## Summary

New Fabric tool **`pbir_fabric_mirror_style`**: given any `app.powerbi.com` report link (or `workspaceId` + `reportId`), pull the source report definition, extract a reusable **style profile**, and apply the transferable parts to the connected report. Closes the gap where an agent asked to "build a report like this one <link>" had no way to capture the source's look.

## What the style profile contains

Extracted by the new `src/styleMirror.ts` module from PBIR definition parts:

| Section | Contents |
|---|---|
| `customTheme` / `baseTheme` | Full custom theme JSON (from `StaticResources/RegisteredResources`) + base theme name |
| `tabs` | Page names, display names, order, hidden flags, active page |
| `pageSize` | Canvas dimensions |
| `banner` | Top-band visuals (y ≤ 8, width ≥ 50% page): geometry, fills, text, fonts, image resources — the header-row spec |
| `navTabs` | Whether the source uses in-page navigation (`pageNavigator` / `actionButton`) |
| `typography` | Frequency tallies of title font families, sizes, colours across all visuals |
| `imageResources` | Logos/images from `StaticResources` with payloads (copied on apply) |
| `visualExemplars` | First raw `objects` + `visualContainerObjects` per visual type — the "detailed settings" needed to mirror component styling |

## Apply behaviour

With a connected report and `apply=true` (default): writes the custom theme + registers it in `report.json`, copies image resources, and returns `bannerSpec` + tab order + notes for the agent to replicate structure with `pbir_create_page` / `pbir_add_visual`. Exemplars are kept out of the default response payload (size); persist everything with `saveProfilePath`.

## Implicit-behaviour contract

The tool description instructs agents: **when a user shares a report link in a build/restyle/match context — even without the word "mirror" — call this tool first** and use its profile. This makes link-driven style mirroring the default behaviour rather than an explicit ask.

## Graceful degradation

Source definitions are not always readable (report in another user's personal workspace, no export permission, tenant restrictions). The tool then returns `access: "partial"` with:

- tab names/order from the Power BI `reports/{id}/pages` API (works with plain shared access),
- a `gaps[]` array stating exactly what could not be read and why,
- concrete unlock guidance (move/copy to a shared workspace, grant workspace access, allow download).

`groups/me` links resolve to the signed-in user's own personal workspace via the new `FabricApiClient.listWorkspaces()`; someone else's My-workspace report degrades as above.
