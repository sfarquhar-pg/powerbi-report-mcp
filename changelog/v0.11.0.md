# v0.11.0 — Style consistency audit tool

## Why

Three field sessions in a row shipped styling regressions that no existing gate could catch: card values clipping/scrolling inside too-small containers, slicers rendering with no visible label, a font system drifting across visuals, a malformed measure filter that made a table silently fail to load, and borders dropping off a minority of visuals. `pbir_validate_wireframe` sees geometry only. This release adds the missing gate.

## New tool: `pbir_audit_style_consistency`

Read-only audit over every visual of the connected report (`src/styleAudit.ts`, pure + unit-tested):

| Code | Catches |
|---|---|
| `CARD_OVERFLOW` | callout+title height estimate exceeds the card container — value will clip/scroll |
| `UNLABELED_SLICER` | container title hidden/empty AND slicer header hidden/empty |
| `FONT_VIOLATION` | any `fontFamily`/`fontFace` outside the caller's `fontAllowlist` |
| `MEASURE_FILTER_MISMATCH` | `filterConfig` measure filters whose `From`/`Where` don't reference the declared field — the visual fails to load at runtime |
| `BORDER_INCONSISTENT` | minority of a visual type deviating from that type's explicit border convention (≥70% majority rule) |

Always returns a `fontCensus` (every font in use with counts) and `stats`. Documented in `skills/wireframes.md` as a publish gate alongside the wireframe validator.
