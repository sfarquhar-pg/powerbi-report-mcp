# v0.10.1 — PBIR-Legacy support for style mirroring

## Summary

`pbir_fabric_mirror_style` (and `extractStyleProfile`) now understands **PBIR-Legacy** report definitions — the single-root `report.json` format that `getDefinition` returns for reports not yet upgraded to the enhanced PBIR folder format. v0.10.0 returned an empty profile (no tabs, no banner, no typography) for such reports; the format is still common for reports authored before the PBIR GA.

## Changes

- `extractStyleProfile()` detects a root `report.json` without `definition/report.json` and routes to a legacy converter:
  - `sections[]` → `tabs` (name/displayName/ordinal/hidden) + `pageSize`
  - `visualContainers[].config` (JSON-string) → banner detection, typography tallies, per-type exemplars (from `singleVisual.objects` / `vcObjects`), nav-tab detection
  - report `config` (JSON-string) → base/custom theme resolution
  - `StaticResources/**/RegisteredResources` images collected with payloads as before
- Banner detection improved for both formats: the top band is derived from full-width shapes anchored at y ≤ 8, then **any** element inside the band (logo images, titles at y≈10, page navigators at y≈29) is captured — previously only elements at y ≤ 8 were.
- A `gaps[]` note marks profiles converted from legacy so agents know geometry came from `layouts[].position`.
- 4 new legacy assertions in `scripts/test-mirror-style.js` (12 → 16).

## Versions

`package.json` / `package-lock.json` / `src/index.ts` 0.10.0 → 0.10.1.
